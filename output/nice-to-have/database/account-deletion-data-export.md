# Feature: Account Deletion & Data Export (Database)

## Overview

Database schema and data management for GDPR-compliant account deletion and data export functionality. This includes tables for tracking export requests, deletion requests, download audit logs, and deletion audit trails. The schema supports data retention policies, grace period management, and compliance auditing.

## Database Schema

### DataExportRequests Table

Tracks all data export requests from users with status and file information.

```sql
CREATE TABLE DataExportRequests (
  request_id VARCHAR(36) PRIMARY KEY COMMENT 'Unique identifier for export request',
  user_id VARCHAR(36) NOT NULL COMMENT 'User who requested export',
  request_status ENUM('pending', 'processing', 'completed', 'failed') DEFAULT 'pending' COMMENT 'Current status of export request',
  file_format ENUM('json', 'csv') DEFAULT 'json' COMMENT 'Requested export file format',
  export_file_url VARCHAR(500) COMMENT 'Pre-signed URL for downloading export file',
  file_size BIGINT COMMENT 'Size of export file in bytes',
  requested_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT 'When export was requested',
  completed_at TIMESTAMP NULL COMMENT 'When export generation completed',
  expires_at TIMESTAMP NULL COMMENT 'When export file expires (30 days after completion)',
  error_message TEXT COMMENT 'Error details if export failed',
  FOREIGN KEY (user_id) REFERENCES Users(user_id) ON DELETE CASCADE,
  INDEX idx_user_export_requests (user_id) COMMENT 'Fast lookup of user export requests',
  INDEX idx_request_status (request_status) COMMENT 'Monitor pending/processing requests',
  INDEX idx_requested_at (requested_at) COMMENT 'Time-based queries',
  INDEX idx_expires_at (expires_at) COMMENT 'Identify expired exports for cleanup'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='Tracks user data export requests for GDPR compliance';
```

**Column Details**:
- `request_id`: UUID generated by application
- `user_id`: Foreign key to Users table
- `request_status`: Lifecycle status of export request
  - pending: Request created, waiting for processing
  - processing: Background job generating export
  - completed: Export ready for download
  - failed: Export generation failed
- `file_format`: User-selected format (JSON or CSV)
- `export_file_url`: Pre-signed URL valid for 30 days
- `file_size`: Used for display and storage monitoring
- `requested_at`: Timestamp for rate limiting calculations
- `completed_at`: When export became available
- `expires_at`: 30 days after completed_at
- `error_message`: Detailed error for debugging


### AccountDeletionRequests Table

Tracks all account deletion requests with grace period and cancellation support.

```sql
CREATE TABLE AccountDeletionRequests (
  request_id VARCHAR(36) PRIMARY KEY COMMENT 'Unique identifier for deletion request',
  user_id VARCHAR(36) NOT NULL COMMENT 'User who requested account deletion',
  request_status ENUM('pending', 'cancelled', 'completed') DEFAULT 'pending' COMMENT 'Current status of deletion request',
  deletion_reason ENUM('privacy_concerns', 'switching_platform', 'no_longer_needed', 'poor_experience', 'other') COMMENT 'User-provided reason for deletion',
  feedback TEXT COMMENT 'Optional user feedback about deletion',
  requested_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT 'When deletion was requested',
  grace_period_ends_at TIMESTAMP NOT NULL COMMENT 'When grace period expires (30 days after request)',
  cancellation_token VARCHAR(255) UNIQUE NOT NULL COMMENT 'Secure token for email-based cancellation',
  cancelled_at TIMESTAMP NULL COMMENT 'When deletion request was cancelled',
  completed_at TIMESTAMP NULL COMMENT 'When account deletion was completed',
  FOREIGN KEY (user_id) REFERENCES Users(user_id) ON DELETE CASCADE,
  INDEX idx_user_deletion_requests (user_id) COMMENT 'Fast lookup of user deletion requests',
  INDEX idx_request_status (request_status) COMMENT 'Monitor pending deletion requests',
  INDEX idx_grace_period_ends_at (grace_period_ends_at) COMMENT 'Identify requests ready for deletion',
  INDEX idx_cancellation_token (cancellation_token) COMMENT 'Fast lookup for email cancellation'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='Tracks account deletion requests with grace period';
```

**Column Details**:
- `request_id`: UUID generated by application
- `user_id`: Foreign key to Users table
- `request_status`: Lifecycle status of deletion request
  - pending: Request created, in grace period
  - cancelled: User cancelled deletion during grace period
  - completed: Account permanently deleted
- `deletion_reason`: Optional categorized reason
- `feedback`: Optional free-text feedback
- `requested_at`: Timestamp for audit trail
- `grace_period_ends_at`: 30 days after requested_at
- `cancellation_token`: Secure random token for email links
- `cancelled_at`: Timestamp when cancelled
- `completed_at`: Timestamp when deletion executed

### DataExportDownloads Table

Audit log of all export file downloads for security monitoring.

```sql
CREATE TABLE DataExportDownloads (
  download_id VARCHAR(36) PRIMARY KEY COMMENT 'Unique identifier for download event',
  request_id VARCHAR(36) NOT NULL COMMENT 'Export request that was downloaded',
  user_id VARCHAR(36) NOT NULL COMMENT 'User who downloaded export',
  downloaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT 'When download occurred',
  ip_address VARCHAR(45) COMMENT 'IP address of download request',
  user_agent TEXT COMMENT 'Browser/client user agent',
  FOREIGN KEY (request_id) REFERENCES DataExportRequests(request_id) ON DELETE CASCADE,
  FOREIGN KEY (user_id) REFERENCES Users(user_id) ON DELETE CASCADE,
  INDEX idx_request_downloads (request_id) COMMENT 'Track downloads per export',
  INDEX idx_user_downloads (user_id) COMMENT 'Track user download activity',
  INDEX idx_downloaded_at (downloaded_at) COMMENT 'Time-based audit queries'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='Audit log of data export downloads';
```

**Column Details**:
- `download_id`: UUID generated by application
- `request_id`: Foreign key to DataExportRequests
- `user_id`: Foreign key to Users (for audit)
- `downloaded_at`: Timestamp of download
- `ip_address`: IPv4 or IPv6 address
- `user_agent`: Full user agent string for forensics


### AccountDeletionAuditLog Table

Comprehensive audit trail of all account deletion activities for compliance.

```sql
CREATE TABLE AccountDeletionAuditLog (
  log_id VARCHAR(36) PRIMARY KEY COMMENT 'Unique identifier for audit log entry',
  user_id VARCHAR(36) NOT NULL COMMENT 'User associated with deletion activity',
  request_id VARCHAR(36) COMMENT 'Deletion request associated with activity',
  action ENUM('request_created', 'request_cancelled', 'deletion_completed', 'reminder_sent') NOT NULL COMMENT 'Type of deletion activity',
  action_details TEXT COMMENT 'Additional details about the action',
  performed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT 'When action was performed',
  ip_address VARCHAR(45) COMMENT 'IP address of request (if applicable)',
  user_agent TEXT COMMENT 'Browser/client user agent (if applicable)',
  FOREIGN KEY (user_id) REFERENCES Users(user_id) ON DELETE CASCADE,
  FOREIGN KEY (request_id) REFERENCES AccountDeletionRequests(request_id) ON DELETE SET NULL,
  INDEX idx_user_deletion_audit (user_id) COMMENT 'Fast lookup of user deletion audit trail',
  INDEX idx_request_audit (request_id) COMMENT 'Fast lookup of request audit trail',
  INDEX idx_performed_at (performed_at) COMMENT 'Time-based audit queries'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='Audit trail of account deletion activities';
```

**Column Details**:
- `log_id`: UUID generated by application
- `user_id`: Foreign key to Users
- `request_id`: Foreign key to AccountDeletionRequests (nullable)
- `action`: Type of activity being logged
  - request_created: User requested account deletion
  - request_cancelled: User cancelled deletion request
  - deletion_completed: Account permanently deleted
  - reminder_sent: Grace period reminder email sent
- `action_details`: JSON or text with additional context
- `performed_at`: Timestamp of action
- `ip_address`: IPv4 or IPv6 address (if user-initiated)
- `user_agent`: Full user agent string (if user-initiated)

## Data Relationships

### Foreign Key Relationships

**DataExportRequests**:
- `user_id` → Users(user_id) ON DELETE CASCADE
  - When user is deleted, all export requests are deleted
  - Cascade ensures no orphaned export requests

**AccountDeletionRequests**:
- `user_id` → Users(user_id) ON DELETE CASCADE
  - When user is deleted, all deletion requests are deleted
  - Cascade ensures no orphaned deletion requests

**DataExportDownloads**:
- `request_id` → DataExportRequests(request_id) ON DELETE CASCADE
  - When export request is deleted, all download logs are deleted
- `user_id` → Users(user_id) ON DELETE CASCADE
  - When user is deleted, all download logs are deleted

**AccountDeletionAuditLog**:
- `user_id` → Users(user_id) ON DELETE CASCADE
  - When user is deleted, all audit logs are deleted
- `request_id` → AccountDeletionRequests(request_id) ON DELETE SET NULL
  - When deletion request is deleted, audit logs remain but request_id is nulled
  - Preserves audit trail even if request is deleted

## Data Retention Queries

### Identify Expired Export Files

```sql
SELECT request_id, user_id, export_file_url, expires_at
FROM DataExportRequests
WHERE request_status = 'completed'
  AND expires_at <= NOW()
ORDER BY expires_at ASC;
```

### Identify Deletion Requests Ready for Processing

```sql
SELECT request_id, user_id, grace_period_ends_at
FROM AccountDeletionRequests
WHERE request_status = 'pending'
  AND grace_period_ends_at <= NOW()
ORDER BY grace_period_ends_at ASC;
```

### Identify Deletion Requests Needing Reminders

```sql
-- 7-day reminder
SELECT request_id, user_id, grace_period_ends_at
FROM AccountDeletionRequests
WHERE request_status = 'pending'
  AND grace_period_ends_at BETWEEN NOW() AND DATE_ADD(NOW(), INTERVAL 7 DAY)
  AND NOT EXISTS (
    SELECT 1 FROM AccountDeletionAuditLog
    WHERE AccountDeletionAuditLog.request_id = AccountDeletionRequests.request_id
      AND action = 'reminder_sent'
      AND action_details LIKE '%7-day%'
  );

-- 1-day reminder
SELECT request_id, user_id, grace_period_ends_at
FROM AccountDeletionRequests
WHERE request_status = 'pending'
  AND grace_period_ends_at BETWEEN NOW() AND DATE_ADD(NOW(), INTERVAL 1 DAY)
  AND NOT EXISTS (
    SELECT 1 FROM AccountDeletionAuditLog
    WHERE AccountDeletionAuditLog.request_id = AccountDeletionRequests.request_id
      AND action = 'reminder_sent'
      AND action_details LIKE '%1-day%'
  );
```

### Check Rate Limit for Data Export

```sql
SELECT COUNT(*) as recent_requests
FROM DataExportRequests
WHERE user_id = ?
  AND requested_at >= DATE_SUB(NOW(), INTERVAL 30 DAY);
```

If `recent_requests > 0`, user has exceeded rate limit.

### Get Next Available Export Request Date

```sql
SELECT DATE_ADD(MAX(requested_at), INTERVAL 30 DAY) as next_available_date
FROM DataExportRequests
WHERE user_id = ?
  AND requested_at >= DATE_SUB(NOW(), INTERVAL 30 DAY);
```


## Data Deletion Queries

### Delete Personal Data (Account Deletion)

```sql
-- Start transaction for data consistency
START TRANSACTION;

-- Delete profile photos
DELETE FROM ProfilePhotos WHERE user_id = ?;

-- Delete verification documents
DELETE FROM VerificationDocuments WHERE user_id = ?;

-- Delete saved preferences
DELETE FROM SavedPreferences WHERE user_id = ?;

-- Delete privacy settings
DELETE FROM PrivacySettings WHERE user_id = ?;

-- Delete login history
DELETE FROM LoginHistory WHERE user_id = ?;

-- Delete support tickets
DELETE FROM SupportTickets WHERE user_id = ?;

-- Delete communications
DELETE FROM Communications WHERE user_id = ?;

-- Anonymize booking history (retain for analytics)
UPDATE Bookings 
SET customer_name = CONCAT('Deleted User ', ?),
    customer_email = NULL,
    customer_phone = NULL
WHERE user_id = ?;

-- Anonymize transaction records (retain for 7 years)
UPDATE Payments
SET customer_name = CONCAT('Deleted User ', ?),
    customer_email = NULL
WHERE user_id = ?;

-- Update user record
UPDATE Users
SET first_name = 'Deleted',
    last_name = 'User',
    email = CONCAT('deleted_', ?, '@deleted.local'),
    phone = NULL,
    address = NULL,
    date_of_birth = NULL,
    bio = NULL,
    account_status = 'deleted'
WHERE user_id = ?;

-- Update deletion request
UPDATE AccountDeletionRequests
SET request_status = 'completed',
    completed_at = NOW()
WHERE request_id = ?;

-- Log deletion completion
INSERT INTO AccountDeletionAuditLog (
  log_id, user_id, request_id, action, action_details, performed_at
) VALUES (
  UUID(), ?, ?, 'deletion_completed', 'Account permanently deleted', NOW()
);

COMMIT;
```

### Cleanup Expired Export Files

```sql
-- Delete expired export requests
DELETE FROM DataExportRequests
WHERE request_status = 'completed'
  AND expires_at <= NOW();
```

Note: Before deleting database records, delete actual files from storage (S3, Azure Blob).

## Technology Stack

- **Database**: MySQL 8.0+ with InnoDB storage engine
- **Character Set**: utf8mb4 for full Unicode support
- **Collation**: utf8mb4_unicode_ci for case-insensitive comparisons
- **Storage Engine**: InnoDB for ACID compliance and foreign key support
- **Backup Strategy**: Daily full backups, hourly incremental backups
- **Retention**: 7-year retention for audit logs and transaction records

## Implementation Notes

### Data Integrity
- Use transactions for account deletion to ensure atomicity
- Foreign key constraints ensure referential integrity
- Cascade deletes prevent orphaned records
- Unique constraints on cancellation_token prevent duplicates

### Performance Considerations
- Indexes on frequently queried columns (user_id, status, timestamps)
- Composite indexes for complex queries if needed
- Regular ANALYZE TABLE to update statistics
- Monitor slow query log for optimization opportunities
- Consider partitioning for very large audit tables (by year)

### Security Considerations
- Encrypt sensitive data at rest (export_file_url, cancellation_token)
- Use parameterized queries to prevent SQL injection
- Limit database user permissions (principle of least privilege)
- Audit database access logs
- Secure backup storage with encryption

### Compliance Considerations
- Retain audit logs for 7 years for compliance
- Retain transaction records for 7 years for accounting/tax
- Document data retention policy in database comments
- Implement automated data retention enforcement
- Regular compliance audits of deletion processes
